Fora do volante: o Claude termina a tarefa sem você vigiando

Você pode parar de vigiar o Claude, de clicar em permitir e de descobrir o erro só no fim: o time do Claude Code já parou. O método é sair do volante, em três trocas.

Entender em 3 minutos Ver no GitHub
Em resumo

Quem usa o Claude Code costuma ficar olhando cada passo, clica em "permitir" a toda hora e só descobre no fim que a tarefa não estava pronta. Fora do volante é um método em três trocas, tirado de uma palestra do time do Claude Code, na Anthropic, e um kit grátis para copiar no seu projeto. Serve para quem usa o Claude Code no dia a dia, com código ou com texto. Para entender, basta ler esta página; para usar o kit, você precisa do Claude Code e do Python 3.

O problema

Três hábitos que prendem você ao volante

Você pede uma tarefa e não consegue sair de perto. Cada um destes hábitos parece cuidado, mas custa o seu tempo e ainda deixa o erro passar.

👀 Você vigia

Lê cada linha que o Claude escreve, com medo de ele esquecer uma regra. Muitas vezes a regra está num CLAUDE.md enorme, cheio de IMPORTANTE em maiúscula, que mais atrapalha do que ajuda.

🖱️ Você aprova tudo

Clica em "permitir" comando por comando, e com tanto clique a leitura vira reflexo. No estudo mostrado na palestra, as pessoas pegaram só 14% dos comandos perigosos.

🏁 Você descobre no fim

O Claude diz "pronto" e para. O erro aparece depois, quando você testa, ou quando o cliente reclama.

2.500 → 30.000+mudanças de código por dia no time do Claude Code: 2.500 em maio, mais de 30.000 em setembro (slide da palestra).
14%dos comandos perigosos foram pegos pelas pessoas que aprovavam um por um (estudo mostrado na palestra).
89%dos comandos perigosos foram barrados pelo auto mode, no mesmo estudo mostrado na palestra.

Fonte: palestra de Lydia Hallie, do time do Claude Code na Anthropic (link em De onde vem). O estudo dos 14% e 89% foi mostrado na palestra e não está publicado na página oficial da Anthropic.

O método

As três trocas, num exemplo só: mudar o login para uma API nova

A mesma tarefa acompanha as três trocas. API é a porta pela qual o seu sistema conversa com outro: aqui, o login deixa a porta velha e passa a usar a nova.

1

Pare de vigiar: um CLAUDE.md enxuto

O CLAUDE.md é o bilhete que o Claude lê antes de começar. Deixe nele só o que o Claude não descobre lendo o código. Para cada linha, pergunte: "ele descobriria isso sozinho?" Se sim, apague.

E escreva com calma. Nos modelos de hoje, IMPORTANTE e NUNCA em maiúscula deixam o resultado pior, não melhor.

No login: "clientes antigos ainda entram pelo app do celular, não remova o código antigo" fica, porque o código não conta isso. "O projeto é em Python" sai, porque ele vê sozinho.
2

Pare de aprovar tudo: o teste do desfazer

Deixe o Claude seguir sozinho com o auto mode, um modo em que um verificador automático decide o que pode rodar. Para o resto, faça uma pergunta: "se o Claude errar isso uma vez, dá para voltar atrás?"

Dá para voltar (editar código, tudo que o git desfaz): deixe com ele. Não dá (apagar trabalho, ler senha, mandar algo para fora): vira uma regra de bloqueio na configuração. Regra no prompt é um pedido; regra na configuração vale antes do auto mode e em todos os modos.

A regra olha o texto do comando, não o que ele faz. Por isso o kit liga também o sandbox, uma caixa fechada em que o comando só lê as pastas e só fala com os sites que você liberou.

No login: editar o arquivo do login tem volta, então ele segue sozinho. Ler o arquivo .env, onde está a senha da API nova, não tem volta: a regra barra.
3

Confira no caminho: diga como é pronto

"Mude o login para a API nova" pode chegar a lugares bem diferentes que, de longe, parecem todos certos:

EsqueceuMudou, mas o login ainda chama a API velha.✗ não está pronto
DeslogouMudou e derrubou quem já estava logado.✗ não está pronto
CertoUsa a API nova e ninguém perdeu a sessão.✓ pronto

Por isso o pedido diz como é pronto ("o login usa a API nova e ninguém é deslogado"), e cada parte tem uma checagem. Quem cobra é um hook: um script que o Claude Code roda sozinho quando o Claude tenta parar. Se a checagem falhar, o hook responde com o código 2, que quer dizer "volte e conserte". Com o código 1, o Claude Code só mostra o erro e o Claude segue como se estivesse feito.

No login: o kit traz as três versões. O hook manda o Claude voltar nas duas erradas e deixa parar só na certa.
A prova

O hook barrou o "pronto", e o Claude voltou e consertou

Não é teoria. O hook do kit foi rodado de verdade no Claude Code. Para isolar só o hook, a prova usou uma pasta de teste pequena, com um erro de propósito: a função soma subtraía em vez de somar. O mesmo hook cobra o login no passo 7 do guia.

  1. O Claude disse "pronto" e tentou parar.
    O pedido era só esse: "Responda só: pronto."
  2. O hook rodou o teste, viu a falha e respondeu com 2.
    Junto, mandou a saída do teste dizendo o que quebrou.
  3. O Claude voltou, achou o erro, consertou e conferiu de novo.
    Só parou quando o teste passou.
"O teste falhava porque soma() em calc.py subtraía em vez de somar (a - b). Troquei para a + b e rodei a checagem de novo: o teste passa (OK)."

Resposta final do Claude. Claude Code 2.1.326, pela assinatura, 17/11/2026, no modo acceptEdits (aceita edições sem perguntar). Com o código 1 no lugar do 2, o "pronto" da primeira resposta teria sido a resposta final. Resumo da prova: exemplo/PROVA.md.

Parte técnica

O kit: para quem quer aplicar no próprio projeto

Daqui para baixo é a parte técnica: os arquivos do kit, como eles funcionam e o processo do início ao fim, com os comandos. Você não precisa desta parte para entender o que está acima.

O que é

Os arquivos do kit

Tudo é texto simples para copiar. Nada instala nada sozinho.

ArquivoPara quê

Como funciona

Do pedido ao "pronto" de verdade

Cada troca vira uma peça da configuração. O caminho de uma tarefa fica assim:

Pedido com "pronto é…"→ Claude trabalha no auto mode→ Bloqueio + sandbox barram o que não tem volta→ Claude tenta parar→ Hook roda a checagem→ Falhou: sai com 2, volta · Passou: pronto

Ordem das permissões

As regras têm três listas: deny (bloqueia), ask (pergunta) e allow (libera). O Claude Code confere deny primeiro, antes do verificador do auto mode, e em todos os modos, inclusive bypassPermissions (o modo que não pergunta nada).

Por que Stop e TaskCompleted

São os momentos em que o Claude tenta parar ou fechar uma tarefa. PostToolUse não bloqueia nem com 2, porque a ferramenta já rodou.

Proteção contra laço

O pronto.sh bloqueia no máximo 3 vezes seguidas (PRONTO_MAX). Depois avisa e deixa parar, para você olhar.

De onde o hook tira a checagem, nesta ordem: a variável PRONTO_CMD, o arquivo .claude/pronto.cmd (uma linha) ou a detecção de npm test / python3 -m unittest. Sem nada para checar, ele não bloqueia. No exemplo do login, a checagem são os testes de exemplo/login-api/tests/: um confere que o login usa a API nova, o outro que ninguém é deslogado.

# .claude/pronto.cmd do exemplo do login
python3 -m unittest discover -s tests -q

Se você juntar um grep à checagem, confira que a pasta existe: ! grep -rn "x" src/ passa sempre quando não há src/, e aí o "pronto" sai falso.

O sandbox do kit só libera a rede para github.com, pypi.org, files.pythonhosted.org e registry.npmjs.org. Se o seu projeto fala com outro site (a API nova do login, por exemplo), acrescente o domínio em sandbox.network.allowedDomains no .claude/settings.json.

Pré-requisitos

O que você precisa

Pouca coisa. O kit e os testes usam só o que já vem no Python 3.

Claude Code

Com o seu projeto aberto nele. O kit foi provado no Claude Code 2.1.326; os comandos /auto-mode-setup, /sandbox e /doctor prompt-audit foram usados nessa versão.

claude --version

Python 3 e git

Para o conferidor, os testes e para baixar o kit.

python3 --version
git --version

Sandbox no Linux/WSL2

O sandbox precisa de bubblewrap e socat. No macOS não precisa instalar nada.

# Debian/Ubuntu
sudo apt install bubblewrap socat
Guia de uso · passo a passo

O processo, do início ao fim

Troque ~/meu-projeto pela pasta do seu projeto. ⚙️ = script, 🧠 = você (às vezes junto com o Claude).

0

Baixar o kit 🧠 você

Clone o repositório e entre na pasta.

git clone https://github.com/inematds/fora-do-volante.git
cd fora-do-volante
1

Conferir o seu projeto ⚙️ script

Mostra o que falta em cada troca. Na primeira vez, é normal aparecerem falhas: é o seu ponto de partida.

python3 ferramentas/conferir_volante.py ~/meu-projeto  # [falha] troca 2 de 3: ... / fora do volante: N falha(s)
2

Copiar a configuração e o hook 🧠 você

O -n não sobrescreve nada (em versões novas do cp ele imprime um aviso sobre o -n; é normal): se o seu projeto já tem um .claude/settings.json, ele fica como está e você junta as chaves do kit à mão. O hook anota as voltas em .claude/.pronto-bloqueios; ponha esse arquivo no .gitignore do projeto.

cp -rn kit/.claude ~/meu-projeto/
echo ".claude/.pronto-bloqueios" >> ~/meu-projeto/.gitignore
3

Dizer qual é a checagem de "pronto" 🧠 você

Uma linha com o comando que prova que a tarefa está pronta. Troque pelo comando de teste do seu projeto (npm test, pytest…): se ele falhar sempre, o hook segura cada parada até 3 vezes. Use o modelo de kit/como-e-pronto.md no pedido.

echo "python3 -m unittest discover -s tests -q" > ~/meu-projeto/.claude/pronto.cmd
4

Ligar o auto mode e ajustar à sua casa 🧠 você + Claude

A partir da versão 2.1.283, o Claude Code já começa no auto mode. Se a barra de status não mostra ⏵⏵ auto mode on, abra com a opção abaixo ou aperte Shift+Tab até aparecer. Ele exige um modelo compatível, e uma empresa pode desligá-lo para todos.

Depois, rode /auto-mode-setup: ele rascunha o autoMode.environment, a descrição da sua casa (repositório, serviços, o que é seu) que o verificador do auto mode usa para decidir o que pode rodar. Esse comando existe nos planos Pro, Max, Ultra, Team e Enterprise e com chave do Claude Console. Os dois são do próprio Claude Code, não do kit.

claude --permission-mode auto   # ou Shift+Tab até "⏵⏵ auto mode on"
/auto-mode-setup
5

Ligar e testar o sandbox 🧠 você

No Claude Code. No Linux/WSL2, instale antes bubblewrap e socat (pré-requisitos).

/sandbox
6

Enxugar o CLAUDE.md 🧠 você + Claude

Rode a auditoria e faça o teste "ele descobriria isso lendo o código?" em cada linha. Modelo: kit/CLAUDE.md.exemplo.

/doctor prompt-audit
7

Ver o hook cobrar ⚙️ script

Roda o hook nas três versões do login. As duas erradas saem com 2; a certa, com 0.

bash exemplo/rodar.sh
esqueceu: saída 2 → o Claude volta e conserta
deslogou: saída 2 → o Claude volta e conserta
certo: saída 0 → pronto de verdade
8

Conferir de novo ⚙️ script

O mesmo comando do passo 1. Terminou quando aparece fora do volante: ok. O conferidor lê os arquivos (regras de bloqueio, sandbox ligado, hook de parada, CLAUDE.md); ele não sabe se você rodou os passos 4 e 5 dentro do Claude Code.

python3 ferramentas/conferir_volante.py ~/meu-projeto  # fora do volante: ok
Testes

O próprio kit se confere

11 testes cobrem o hook (sai com 2, com 0, para depois do máximo, lê o pronto.cmd), o exemplo do login e o conferidor. Só precisam do Python 3.

python3 -m unittest discover -s tests -v   # Ran 11 tests ... OK
