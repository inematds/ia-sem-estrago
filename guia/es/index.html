Suelta el volante: Claude termina la tarea sin que lo vigiles

Puedes dejar de vigilar a Claude, de hacer clic en permitir y de descubrir el error recién al final: el equipo de Claude Code ya dejó de hacerlo. El método es soltar el volante, en tres cambios.

Entiéndelo en 3 minutos Ver en GitHub
En resumen

Quienes usan Claude Code suelen mirar cada paso, hacen clic en "permitir" a cada rato y solo descubren al final que la tarea no estaba terminada. Suelta el volante es un método en tres cambios, tomado de una charla del equipo de Claude Code en Anthropic, y un kit gratis para copiar en tu proyecto. Sirve para quienes usan Claude Code a diario, con código o con texto. Para entenderlo, basta con leer esta página; para usar el kit, necesitas Claude Code y Python 3.

Explicado en 1 minuto

Para qué sirve soltar el volante

😩 El problema

Quien usa Claude Code se convierte en niñera: vigila cada paso, hace clic en "permitir" todo el tiempo y solo descubre al final que la tarea no quedó lista.

🏢 De dónde salió

De una charla del equipo de Claude Code, en Anthropic. Dejaron de trabajar así y pasaron de 2.500 a más de 30.000 cambios de código por día. El secreto fue quitarle al humano tres tareas y dejar que la máquina las hiciera.

🛞 El método: tres cambios

1. Deja de vigilar: instrucción breve, sin "IMPORTANTE" en mayúsculas, que dificulta el trabajo de los modelos actuales.
2. Deja de aprobarlo todo: deja que el modo automático apruebe; lo irreversible (borrar, leer contraseñas, enviar correos) se convierte en un bloqueo en un archivo, que Claude no puede saltarse.
3. Comprueba sobre la marcha: di qué significa "listo", y una prueba automática hace que Claude vuelva y corrija hasta que esté realmente listo.

🧰 El kit

El método ya preparado para copiarlo en tu proyecto: el archivo de bloqueos listo, el script que exige que esté "listo", un verificador que indica si tu proyecto aplica los tres cambios y un ejemplo con la prueba real.

🧪 La prueba

Le pedimos a Claude solo "di listo", con un error oculto en el código. El bloqueo lo frenó; Claude encontró el error, lo corrigió y solo entonces se detuvo.

🎁 Todo gratis

El kit en GitHub, esta guía en portugués, inglés y español, y videos explicativos: uno para quienes ya usan Claude Code y otro para quienes están empezando.

El problema

Tres hábitos que te mantienen al volante

Pides una tarea y no puedes alejarte. Cada uno de estos hábitos parece cuidado, pero te cuesta tiempo y además deja pasar los errores.

👀 Vigilar

Lees cada línea que escribe Claude por miedo a que olvide una regla. Muchas veces la regla está en un CLAUDE.md enorme, lleno de IMPORTANTE en mayúsculas, que estorba más de lo que ayuda.

🖱️ Aprobar todo

Haces clic en "permitir" comando por comando y, con tantos clics, leer se vuelve un reflejo. En el estudio que se mostró en la charla, las personas detectaron solo el 14% de los comandos peligrosos.

🏁 Descubrirlo al final

Claude dice "terminado" y se detiene. El error aparece después, cuando haces una prueba o cuando se queja el cliente.

2.500 → 30.000+cambios de código por día en el equipo de Claude Code: 2.500 en mayo, más de 30.000 en septiembre (diapositiva de la charla).
14%de los comandos peligrosos fueron detectados por las personas que los aprobaban uno por uno (estudio mostrado en la charla).
89%de los comandos peligrosos fueron bloqueados por auto mode, en el mismo estudio mostrado en la charla.

Fuente: charla de Lydia Hallie, del equipo de Claude Code en Anthropic (enlace en De dónde viene). El estudio del 14% y el 89% se mostró en la charla y no está publicado en la página oficial de Anthropic.

El método

Los tres cambios, con un solo ejemplo: cambiar el inicio de sesión por una API nueva

La misma tarea ilustra los tres cambios. Una API es la puerta por la que tu sistema se comunica con otro: aquí, el inicio de sesión deja la puerta vieja y empieza a usar la nueva.

1

Deja de vigilar: un CLAUDE.md conciso

El CLAUDE.md es la nota que Claude lee antes de empezar. Deja ahí solo lo que Claude no puede descubrir leyendo el código. Para cada línea, pregúntate: "¿podría descubrirlo por su cuenta?" Si sí, bórrala.

Y escribe con calma. En los modelos actuales, IMPORTANTE y NUNCA en mayúsculas empeoran el resultado, no lo mejoran.

En el inicio de sesión: "los clientes antiguos todavía ingresan desde la app del celular, no elimines el código antiguo" se queda, porque el código no indica eso. "El proyecto está hecho en Python" se elimina, porque puede verlo por su cuenta.
2

Deja de aprobar todo: la prueba de deshacer

Deja que Claude avance por su cuenta con auto mode, un modo en el que un verificador automático decide qué puede ejecutarse. Para lo demás, hazte esta pregunta: "si Claude se equivoca una vez con esto, ¿se puede deshacer?"

Se puede deshacer (editar código, todo lo que git puede deshacer): déjaselo. No se puede (borrar trabajo, leer una contraseña, enviar algo afuera): se convierte en una regla de bloqueo en la configuración. Una regla en el prompt es una solicitud; una regla en la configuración se aplica antes de auto mode y en todos los modos.

La regla revisa el texto del comando, no lo que hace. Por eso el kit también activa el sandbox, un entorno aislado en el que el comando solo lee las carpetas y se comunica con los sitios que autorizaste.

En el inicio de sesión: editar el archivo del inicio de sesión se puede deshacer, así que Claude continúa por su cuenta. Leer el archivo .env, donde está la contraseña de la nueva API, no se puede deshacer: la regla lo bloquea.
3

Revisa sobre la marcha: define qué significa terminado

"Cambia el inicio de sesión para que use la API nueva" puede terminar de varias formas que, vistas desde lejos, parecen correctas:

Se olvidóHizo el cambio, pero el inicio de sesión todavía llama a la API vieja.✗ no está terminado
Cerró la sesiónHizo el cambio y desconectó a quienes ya habían iniciado sesión.✗ no está terminado
CorrectoUsa la API nueva y nadie perdió su sesión.✓ terminado

Por eso el pedido define qué significa terminado ("el inicio de sesión usa la API nueva y nadie cierra su sesión") y cada parte tiene una verificación. Quien lo exige es un hook: un script que Claude Code ejecuta por su cuenta cuando Claude intenta detenerse. Si la verificación falla, el hook responde con el código 2, que significa "vuelve y corrige". Con el código 1, Claude Code solo muestra el error y Claude sigue como si estuviera terminado.

En el inicio de sesión: el kit incluye las tres versiones. El hook hace que Claude vuelva a las dos incorrectas y solo le permite detenerse cuando la versión es correcta.
La prueba

El hook bloqueó el "terminado" y Claude volvió y corrigió

No es teoría. El hook del kit se ejecutó de verdad en Claude Code. Para aislar solo el hook, la prueba usó una carpeta de prueba pequeña con un error intencional: la función soma restaba en vez de sumar. El mismo hook verifica el inicio de sesión en el paso 7 de la guía.

  1. Claude dijo "terminado" e intentó detenerse.
    El pedido era solo este: "Responde solo: terminado."
  2. El hook ejecutó la prueba, detectó el fallo y respondió con 2.
    También envió la salida de la prueba, que indicaba qué había fallado.
  3. Claude volvió, encontró el error, lo corrigió y volvió a verificar.
    Solo se detuvo cuando pasó la prueba.
"La prueba fallaba porque soma() en calc.py restaba en vez de sumar (a - b). Lo cambié por a + b y volví a ejecutar la verificación: la prueba pasa (OK)."

Respuesta final de Claude. Claude Code 2.1.326, con la suscripción, 17/11/2026, en modo acceptEdits (acepta ediciones sin preguntar). Con el código 1 en lugar del 2, el "terminado" de la primera respuesta habría sido la respuesta final. Resumen de la prueba: exemplo/PROVA.md (en portugués).

Parte técnica

El kit: para quienes quieren aplicarlo en su propio proyecto

Qué incluye

Cómo funciona

Del pedido al "terminado" de verdad

Cada cambio se convierte en una pieza de la configuración. El recorrido de una tarea es así:

Pedido con "terminado significa…"→ Claude trabaja en auto mode→ El bloqueo + el sandbox impiden lo irreversible→ Claude intenta detenerse→ El hook ejecuta la verificación→ Falló: termina con 2, vuelve · Pasó: terminado

Orden de los permisos

Las reglas tienen tres listas: deny (bloquea), ask (pregunta) y allow (permite). Claude Code revisa deny primero, antes del verificador de auto mode y en todos los modos, incluido bypassPermissions (el modo que no pregunta nada).

Por qué Stop y TaskCompleted

Son los momentos en que Claude intenta detenerse o cerrar una tarea. PostToolUse no bloquea, ni siquiera con 2, porque la herramienta ya se ejecutó.

Protección contra ciclos

pronto.sh bloquea como máximo 3 veces seguidas (PRONTO_MAX). Después avisa y permite que se detenga para que revises.

De dónde obtiene el hook la verificación, en este orden: la variable PRONTO_CMD, el archivo .claude/pronto.cmd (una línea) o la detección de npm test / python3 -m unittest. Si no hay nada que verificar, no bloquea. En el ejemplo del inicio de sesión, la verificación son las pruebas de exemplo/login-api/tests/: una confirma que el inicio de sesión usa la API nueva; la otra, que nadie cierre su sesión.

# .claude/pronto.cmd do exemplo do login
python3 -m unittest discover -s tests -q

Si agregas un grep a la verificación, confirma que la carpeta existe: ! grep -rn "x" src/ siempre pasa cuando no existe src/, y entonces "terminado" sería falso.

El sandbox del kit solo permite la red para github.com, pypi.org, files.pythonhosted.org y registry.npmjs.org. Si tu proyecto se comunica con otro sitio (por ejemplo, la nueva API del inicio de sesión), agrega el dominio en sandbox.network.allowedDomains en .claude/settings.json.

Requisitos previos

Qué necesitas

Muy poco. El kit y las pruebas usan solo lo que ya viene con Python 3.

Claude Code

Con tu proyecto abierto. El kit se probó en Claude Code 2.1.326; en esa versión se usaron los comandos /auto-mode-setup, /sandbox y /doctor prompt-audit.

claude --version

Python 3 y git

Para el verificador, las pruebas y descargar el kit.

python3 --version
git --version

Sandbox en Linux/WSL2

El sandbox necesita bubblewrap y socat. En macOS no hace falta instalar nada.

# Debian/Ubuntu
sudo apt install bubblewrap socat
Guía de uso · paso a paso

El proceso, de principio a fin

Reemplaza ~/mi-proyecto por la carpeta de tu proyecto. ⚙️ = script, 🧠 = tú (a veces junto con Claude).

0

Descargar el kit 🧠 tú

Clona el repositorio y entra en la carpeta.

git clone https://github.com/inematds/fora-do-volante.git
cd fora-do-volante
1

Verificar tu proyecto ⚙️ script

Muestra lo que falta en cada cambio. La primera vez es normal que aparezcan fallos: ese es tu punto de partida.

python3 ferramentas/conferir_volante.py ~/mi-proyecto  # [falha] troca 2 de 3: ... / fora do volante: N falha(s)
2

Copiar la configuración y el hook 🧠 tú

-n no sobrescribe nada (en las versiones nuevas de cp aparece un aviso sobre -n; es normal): si tu proyecto ya tiene un .claude/settings.json, queda como está y agregas a mano las claves del kit. El hook registra los intentos en .claude/.pronto-bloqueios; agrega ese archivo al .gitignore del proyecto.

cp -rn kit/.claude ~/mi-proyecto/
echo ".claude/.pronto-bloqueios" >> ~/mi-proyecto/.gitignore
3

Indicar cómo se verifica que está "terminado" 🧠 tú

Una línea con el comando que demuestra que la tarea está terminada. Reemplázalo por el comando de prueba de tu proyecto (npm test, pytest…): si siempre falla, el hook detiene cada intento hasta 3 veces. Usa el modelo de kit/como-e-pronto.md (en portugués) en el pedido.

echo "python3 -m unittest discover -s tests -q" > ~/mi-proyecto/.claude/pronto.cmd
4

Activar auto mode y adaptarlo a tu entorno 🧠 tú + Claude

Desde la versión 2.1.283, Claude Code ya se inicia en auto mode (verificado el 17/11/2026). Si la barra de estado no muestra ⏵⏵ auto mode on, ábrelo con la opción de abajo o presiona Shift+Tab hasta que aparezca. Requiere un modelo compatible, y una empresa puede desactivarlo para todos.

Después, ejecuta /auto-mode-setup: prepara un borrador de autoMode.environment, la descripción de tu entorno (repositorio, servicios, qué es tuyo) que el verificador de auto mode usa para decidir qué puede ejecutarse. Este comando está disponible en los planes Pro, Max, Ultra, Team y Enterprise, y con una clave de Claude Console. Ambos son parte de Claude Code, no del kit.

claude --permission-mode auto   # o Shift+Tab hasta "⏵⏵ auto mode on"
/auto-mode-setup
5

Activar y probar el sandbox 🧠 tú

En Claude Code. En Linux/WSL2, instala antes bubblewrap y socat (requisitos previos).

/sandbox
6

Hacer más conciso el CLAUDE.md 🧠 tú + Claude

Ejecuta la auditoría y aplica la prueba "¿podría descubrirlo leyendo el código?" a cada línea. Modelo: kit/CLAUDE.md.exemplo (en portugués).

/doctor prompt-audit
7

Ver cómo el hook exige la verificación ⚙️ script

De vuelta en la carpeta del kit, ejecuta el hook en las tres versiones del inicio de sesión. Las dos incorrectas salen con 2; la correcta, con 0.

bash exemplo/rodar.sh
esqueceu: saída 2 → o Claude volta e conserta
deslogou: saída 2 → o Claude volta e conserta
certo: saída 0 → pronto de verdade
8

Volver a verificar ⚙️ script

El mismo comando del paso 1. El proceso termina cuando aparece fora do volante: ok. El verificador lee los archivos (reglas de bloqueo, sandbox activado, hook de detención, CLAUDE.md); no sabe si ejecutaste los pasos 4 y 5 dentro de Claude Code.

python3 ferramentas/conferir_volante.py ~/mi-proyecto  # fora do volante: ok
